## البنية التقنية

- **Next.js 16** (App Router) + **React 19**
- **PostgreSQL** عبر **Drizzle ORM**
- **Tailwind CSS v4**
- **KaTeX** لعرض العبارات والرموز الرياضية، بما فيها رمز π في شعار المنصة (دائمًا باتجاه LTR ومعزولة عن اتجاه النص العربي)
- **lucide-react** للأيقونات

## أوامر التشغيل

```bash
npm run dev        # تطوير
npm run build      # بناء الإنتاج
npm run start      # تشغيل الإنتاج
npx drizzle-kit push   # تطبيق مخطط قاعدة البيانات
TEACHER_PASSWORD=<private-secret> node scripts/seed.mjs  # فهرس صور الكتاب + تهيئة المعلم أول مرة فقط
node scripts/seed-lesson-one.mjs  # الدرس الأول من صور الصفحتين 3 و4
```

## هيكل قاعدة البيانات (src/db/schema.ts)

| الجدول | الغرض |
|---|---|
| `units` / `lessons` | فهرس الكتاب المصوّر المرسل (8 وحدات و33 عنوان درس؛ أحدها غير واضح في الصورة) ومحتوى الدرس المنشور |
| `quiz_questions` | أسئلة اختبارات الدروس والوحدات — مفاتيح الإجابة لا تُرسل قبل تسليم اختبار مكتمل |
| `teacher_solutions` | الحلول التفصيلية للمعلم (محمية) |
| `students` / `lesson_progress` / `quiz_attempts` | بيانات الطلاب وتقدمهم ومحاولاتهم |
| `settings` | تجزئة كلمة مرور المعلم (scrypt + ملح) — لا تُخزن كلمة المرور نصًا |

## الأمان

- منطقة المعلم محمية بكلمة مرور تُمرَّر عبر متغير البيئة `TEACHER_PASSWORD` عند التهيئة الأولى فقط. تُخزَّن التجزئة في قاعدة البيانات، ويمكن تغيير كلمة المرور لاحقًا من منطقة المعلم.
- التحقق يتم في الخادم: كلمة المرور تُجزأ بـ scrypt، والجلسة كوكي httpOnly موقعة بـ HMAC.
- الحلول ومفاتيح الإجابة تُقدَّم عبر مسارات API تتحقق من الجلسة، ولا تصل إلى منطقة الطالب.
- بيانات الطالب منفصلة عن بيانات المعلم.

## تصميم وشرح موحّدان لكل الدروس

- ألوان زاهية مع خلفيات هادئة، وتبويبات جانبية. شرح الدرس الأول موسّع إلى 6 أفكار متدرجة داخل تبويب الشرح، مع أمثلة مفسّرة وأسئلة تحقق.
- يظهر «شرح إضافي للكتاب» على المحتوى الإضافي فقط. صفحات المصدر محفوظة داخليًا ولا تظهر للطالب إلا في التمارين؛ لا تظهر في الترويسة أو الشرح أو الملخص أو دفتر الطالب أو الرسوم.
- `MathText` و`TeX` يعرضان العلاقات بـKaTeX في أغلفة LTR معزولة عن RTL. فحص النشر يرفض الصيغ غير الصالحة والعلاقات النصية غير المنسّقة.
- هذه قواعد للدروس المقبلة، لا تغيير لمصادر الكتاب أو إذنًا بإضافة دروس لم تصل صورها.

## مصدر المحتوى الحالي

- الصورة الأولى: فهرس الكتاب ص 2؛ بُنيت منه بطاقات الوحدات وعناوين الدروس وأرقام صفحاتها في `scripts/seed.mjs`.
- بقية الصور: الدرس الأول «الأعداد الطبيعية» في الصفحتين 3 و4؛ محتواه ودفتره وحلول الكتاب في `src/content/lesson-1.json`؛ بنك الاختبار المستقل في `src/content/assessments/natural-numbers.json`، ويُعتمد عبر `scripts/seed-lesson-one.mjs`.
- عنوان الدرس الذي يبدأ في الصفحة 90 غير مقروء بوضوح في صورة الفهرس؛ يظهر مؤقتًا بوصفه غير واضح حتى تصل صورته. لا يُنشأ له محتوى من التخمين.
- اختبار نهاية الدرس يتكون دائمًا من أسئلة جديدة خارج أمثلته وتمارين الكتاب، ضمن مهاراته فقط. يبقى التدريب من المصدر منفصلًا. تُفحص هذه القاعدة عند استيراد الدرس.
- الرسوم المرجعية للصفحتين 3 و4 معادة بـ SVG وجداول متجهية مع تكبير، منفصلة عن المختبر التفاعلي. سجل المصادر ومعايير الدروس التالية في [قواعد المحتوى](docs/CONTENT_STANDARDS.md).
- يستخدم `scripts/seed-lesson-one.ts` عميل Drizzle، ويؤرشف الاختبار السابق دون حذف تقدم الطلاب أو محاولاتهم؛ الأمر القديم `.mjs` يبقى مدعومًا.

## تمارين الكتاب ودفتر الكتابة

- تمارين الدرس الأول الستة أصبحت مهمات تفاعلية تحفظ معطيات الكتاب: صيد النقاط، محقق المنازل، مطابقة قيمتي 5، مستقيم الأعداد، قيمة 2 في عدد كبير، وشفرة نبتون.
- `/api/practice` يتحقق من الإجابات ويحفظ المحاولة. لا يرسل الحل التعليمي قبل محاولة مكتملة وطلب صريح؛ الحل مفصل وقابل للقراءة خطوة خطوة. لا يقرأ هذا المسار جدول حلول المعلم أو مفاتيح اختبار النهاية.
- `lesson_exercises` و`practice_progress` منفصلان عن أسئلة الاختبار ومحاولاته، مع إصدارات تحفظ البيانات السابقة. يهيئهما `npx drizzle-kit push` بعد تشغيل بيئة المعاينة.
- دفتر الطالب 4 أوراق لما يكتبه الطالب في دفتره: تعريفات وقواعد ورسوم وأمثلة بحلول كاملة. ليس هو تبويب الملخص. الطباعة تشمل جميع الأوراق، والعلامات والملاحظات الشخصية تحفظ محليًا في المتصفح فقط.

## آلية إضافة الدروس

لا يُنشأ أي درس من دون صور الكتاب. عند استلام صور كل درس:

1. يُستخرج محتوى الكتاب ويُنظَّم.
2. يُبنى شرح موسّع مميّز عن محتوى الكتاب.
3. تُضاف الأنشطة التفاعلية والمختبر.
4. يُنشأ اختبار نهاية الدرس بأسئلة جديدة من خارج أمثلته وتمارين الكتاب، وتُضاف الحلول ومفاتيح التصحيح إلى منطقة المعلم.
5. يُنشأ دفتر الطالب ليكون المرحلة الأخيرة في صفحة الدرس.
6. يُنشر **الدرس والاختبار والدفتر والحلول في العملية نفسها** عبر `publishLessonWithAssessment`، دون مهمة لاحقة أو طلب إضافي من المالك. لا يُسمح بالنشر إذا غاب الاختبار أو لم تكتمل الحزمة؛ فشل أي جزء يلغي المعاملة كاملة.

اختبار الدرس متاح فور اكتمال إضافته، أما اختبار الوحدة فلا يُنشأ إلا بعد تأكيد المالك الصريح بأن الوحدة اكتملت.
